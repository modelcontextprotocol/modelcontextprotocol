Skills over MCP lets a server publish workflow instructions alongside its tools.
An agent can discover a skill, load its `SKILL.md` when needed, and read supporting
files through MCP resources. The skill format comes from the
[Agent Skills specification](https://agentskills.io/specification); this extension
defines how those skills are discovered and retrieved over MCP.

<Note>

[SEP-2640](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/2640)
has been [accepted by the Core Maintainers](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/2640#issuecomment-5532996112).
Finalization is in progress. Implementations may target different revisions or
only part of the extension; see [implementation support](#implementation-support).

</Note>

## When to use Skills over MCP

Use this extension to distribute instructions that explain how to combine a
server's tools, follow a multi-step workflow, or consult supporting reference
material. The instructions can be maintained and served through the same MCP
connection as the tools they describe.

Skills remain optional. Clients that do not implement the extension can continue
using the server's ordinary tools and resources. Supporting local Agent Skills or
generic MCP resource reads alone does not establish support for this extension.

## How it works

1. **Detect support.** The server advertises `io.modelcontextprotocol/skills` in
   `capabilities.extensions`, alongside the base `resources` capability. Clients
   check that declaration before calling the extension methods.
2. **Discover skills.** `skills/list` returns a paginated catalog. Each entry
   contains the URI of its `SKILL.md`, its frontmatter, and a complete file
   manifest with SHA-256 digests and byte sizes, or the explicit `"dynamic"` marker.
3. **Resolve a skill.** `skills/get` returns the entry for a known `SKILL.md` URI,
   including skills the server does not enumerate.
4. **Read on demand.** `resources/read` retrieves the skill's instructions and
   supporting files as needed. Hosts verify static content against its manifest
   and apply the specification's consent and origin-isolation requirements.
5. **Browse directories when available.** Servers may additionally advertise
   `directoryRead: true` to enable `resources/directory/read` for direct children
   of a directory resource.

The conventional URI is `skill://<skill-path>/SKILL.md`; other resource schemes
are supported. A skill's identity includes both its originating server and its
URI. A URI scheme alone does not establish that a resource is a skill.

The current specification uses individually addressable resources. The earlier
`skill://index.json` catalog and archive distribution are not the current
discovery and retrieval contract.

## Implementation support

Last checked: **2026-09-08**. These tables track documented implementation scope,
not conformance certification. **Available subset** means a documented product
flow with stated limits; **merged** means code has landed but does not establish
release availability; **open PR** and **draft PR** mean proposed support.

### Clients and products

| Client or product         | Status                         | Supported flow and limits                                                                                                                                                                                                      | Evidence                                                                                                                                                          |
| ------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ChatGPT plugin submission | Available subset               | Imports a static snapshot using `skills/list`, `skills/get`, and digest-verified `resources/read`. Limited to five skills, 100 files per skill, and 5 MiB per skill; this is submission-time import, not live runtime loading. | [Product documentation](https://developers.openai.com/plugins/build/mcp-server#import-skills-from-the-mcp-server)                                                 |
| fast-agent                | Available subset, pinned draft | Registry browsing and installation using `skills/list`, `skills/get`, and manifest-verified resource reads. Documentation pins revision `d7490ec`; installed skills are local copies, not live MCP resource readers.           | [Compatibility and scope](https://github.com/evalstate/fast-agent/blob/main/docs/docs/mcp/skills-over-mcp.md)                                                     |
| MCP Inspector             | Merged                         | Web, CLI, and TUI inspection; paginated listing, entry lookup, optional directory reads, and digest, size, and frontmatter verification. Inspection does not implement agent activation or consent.                            | [Implementation #2251](https://github.com/modelcontextprotocol/inspector/pull/2251), [phase 3 #2293](https://github.com/modelcontextprotocol/inspector/pull/2293) |

See the [Extension Support Matrix](/extensions/client-matrix) for the comparison
across extensions. A missing entry means support has not been verified here.
