Tools describe individual operations. Skills provide the instructions for using
those operations together: a workflow, the decisions along the way, and any
supporting reference material. Skills over MCP lets servers publish those
instructions alongside their tools, so agents can discover and read them through
the same connection.

A skill is a directory containing a `SKILL.md` file and optional supporting
files. The format follows the [Agent Skills specification](https://agentskills.io/specification).
This extension defines discovery and retrieval over MCP.

## Why serve skills over MCP?

- **Keep instructions with the service.** Publish workflows alongside the tools
  they describe and maintain them on the server.
- **Discover available workflows.** Clients can find the skills a connected
  server offers without a separate installation source.
- **Load context as needed.** Clients can inspect skill metadata first, then
  retrieve instructions and supporting files when relevant.

## How Skills work

1. **Capability detection.** The server advertises
   `io.modelcontextprotocol/skills` in `capabilities.extensions`, alongside the
   base `resources` capability. Clients check this declaration before calling
   the extension methods.
2. **Discovery.** `skills/list` returns a paginated catalog. Each entry contains
   the URI of its `SKILL.md`, its frontmatter, and a complete file manifest with
   digests and byte sizes, or the explicit `"dynamic"` marker.
3. **Lookup.** `skills/get` returns the entry for a known `SKILL.md` URI,
   including skills the server does not enumerate.
4. **Retrieval.** `resources/read` retrieves instructions and supporting files
   on demand. Hosts verify static content against the manifest and apply the
   specification's consent and origin-isolation requirements.

Servers can additionally advertise `directoryRead: true` to support
`resources/directory/read`, which lists a directory's direct children.

The conventional URI is `skill://<skill-path>/SKILL.md`; other resource schemes
are supported. A skill's identity includes both its originating server and its
URI.

## Client support

Skills support varies by client. See the [client matrix](/extensions/client-matrix#skills-support)
for implementation scope and availability. Clients that do not implement the
extension can continue using the server's ordinary tools and resources.
