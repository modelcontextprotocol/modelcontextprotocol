This matrix shows which MCP clients support each [official extension](/extensions/overview). Extensions are always opt-in; follow each extension's capability requirements. For [Skills](/extensions/skills/overview), the server declares support and the client checks that declaration before calling the extension methods.

<Note>

This list is maintained by the community. If you notice any inaccuracies or would like to add or update information, please [submit a pull request](https://github.com/modelcontextprotocol/modelcontextprotocol/pulls).

</Note>

## Tasks support

This column tracks the current `io.modelcontextprotocol/tasks` extension
([SEP-2663](https://github.com/modelcontextprotocol/ext-tasks)), rather than the
older experimental Tasks capability. Earlier Tasks support does not by itself
establish support for the current extension.

As of **2026-09-08**, MCP Inspector's `main` branch implements extension
negotiation and the `tasks/get`, `tasks/update`, and `tasks/cancel` flow for
protocol `2026-07-28`. Its [client implementation](https://github.com/modelcontextprotocol/inspector/blob/main/core/mcp/inspectorClient.ts)
and [integration tests](https://github.com/modelcontextprotocol/inspector/blob/main/clients/web/src/test/integration/mcp/inspectorClient-tasks-era.test.ts)
cover the current flow separately from legacy Tasks. This records implementation
on `main`, not verified release availability. Other cells remain unverified;
updates should link to evidence for the current extension and identify the
supported version.

## Adding extension support to your client

If you're building an MCP client and want to implement extension support:

1. Review the extension specification (e.g., in the [ext-auth](https://github.com/modelcontextprotocol/ext-auth) or [ext-apps](https://github.com/modelcontextprotocol/ext-apps) repository)
2. Follow that extension's capability negotiation rules. Where client advertisement is required, declare support in the `extensions` field of `io.modelcontextprotocol/clientCapabilities` in each request's `_meta`. Skills requires checking the server's extension declaration; see [Skills over MCP](/extensions/skills/overview#how-it-works).
3. Implement the extension's protocol requirements
4. Submit a pull request to update this matrix

See [Extensions Overview](/extensions/overview#negotiation) for details on the capability negotiation mechanism.
