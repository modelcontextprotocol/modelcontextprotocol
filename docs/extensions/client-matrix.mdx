This matrix shows which MCP clients support each [official extension](/extensions/overview). Extensions are always opt-in; follow each extension's capability requirements. For [Skills](/extensions/skills/overview), the server declares support and the client checks that declaration before calling the extension methods.

<Note>

This list is maintained by the community. If you notice any inaccuracies or would like to add or update information, please [submit a pull request](https://github.com/modelcontextprotocol/modelcontextprotocol/pulls).

</Note>

## Skills support

Last checked: **2026-09-08**. The Skills column distinguishes the following
implementation scopes:

- **ChatGPT plugin submission — import subset.** Imports a static snapshot using
  `skills/list`, `skills/get`, and digest-verified `resources/read`. The documented
  limits include five skills, 100 files per skill, and 5 MiB per skill. This is
  submission-time import, not live runtime loading. See the
  [product documentation](https://developers.openai.com/plugins/build/mcp-server#import-skills-from-the-mcp-server).
- **fast-agent — install subset.** Registry browsing and manifest-verified
  installation, pinned to draft revision `d7490ec`. Installed skills are local
  copies. See its [compatibility and scope documentation](https://github.com/evalstate/fast-agent/blob/main/docs/docs/mcp/skills-over-mcp.md).
- **MCP Inspector — merged inspection support.** Web, CLI, and TUI inspection,
  including listing, entry lookup, optional directory reads, and digest, size,
  and frontmatter verification. This does not imply agent activation or release
  availability. See [#2251](https://github.com/modelcontextprotocol/inspector/pull/2251)
  and [#2293](https://github.com/modelcontextprotocol/inspector/pull/2293).

Support for local Agent Skills or generic MCP resource reads alone does not
establish Skills extension support. Updates should include a public source,
version or revision where known, and any implementation limits.

## Adding extension support to your client

If you're building an MCP client and want to implement extension support:

1. Review the extension specification (e.g., in the [ext-auth](https://github.com/modelcontextprotocol/ext-auth) or [ext-apps](https://github.com/modelcontextprotocol/ext-apps) repository)
2. Follow that extension's capability negotiation rules. Where client advertisement is required, declare support in the `extensions` field of `io.modelcontextprotocol/clientCapabilities` in each request's `_meta`. Skills requires checking the server's extension declaration; see [Skills over MCP](/extensions/skills/overview#how-skills-work).
3. Implement the extension's protocol requirements
4. Submit a pull request to update this matrix

See [Extensions Overview](/extensions/overview#negotiation) for details on the capability negotiation mechanism.
