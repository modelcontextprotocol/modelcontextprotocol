The TUI brings the web client's interactive exploration into the terminal. It is the right surface when there's no browser available — a remote box over SSH, a locked-down environment, or simply a preference for staying in the terminal.

```bash
npx @modelcontextprotocol/inspector --tui node build/index.js
```

## Choosing servers

Unlike the CLI, the TUI does **not** take `--server` — it loads _every_ server in the file and lets you pick from the list:

```bash
mcp-inspector --tui --catalog mcp.json   # writable catalog, seeded empty if missing (unlike the web client)
mcp-inspector --tui --config mcp.json    # read-only session, errors if absent
```

With no source flag and no ad-hoc target, it uses the default writable catalog `~/.mcp-inspector/mcp.json`. See [Configuration and flags](/docs/draft/tools/inspector/configuration).

## Tabs

| Tab           | Key | What it shows                                                                                   |
| ------------- | --- | ----------------------------------------------------------------------------------------------- |
| **Info**      | `i` | Server info, capabilities, and negotiated protocol details.                                     |
| **Auth**      | `a` | OAuth state — the same fields as the web client's Connection Info — plus **Clear OAuth state**. |
| **Resources** | `r` | Browse and read resources.                                                                      |
| **Prompts**   | `m` | List prompts and render them with arguments.                                                    |
| **Tools**     | `t` | View tools and execute them with form-like inputs.                                              |
| **Protocol**  | `p` | JSON-RPC request/response/notification history.                                                 |
| **Network**   | `n` | HTTP traffic for SSE and Streamable HTTP servers.                                               |
| **Console**   | `o` | `stderr` from a connected stdio server process.                                                 |

The accelerators avoid collisions rather than always taking the first letter: **P**rotocol takes `p` so Pro**m**pts takes `m`, and **C**onsole takes `o` because `c` is the global Connect action.

## Navigation

| Key                | Action                                              |
| ------------------ | --------------------------------------------------- |
| `←` / `→` or `Tab` | Switch tabs                                         |
| `↑` / `↓`          | Move through the current list                       |
| `Enter`            | Select an item, execute a tool, or fetch a resource |
| `c`                | Connect to the selected server                      |
| `d`                | Disconnect                                          |
| `Esc` or `Ctrl+C`  | Exit                                                |

## Authorizing an HTTP server

1. Select an HTTP or SSE server and press **`c`** to connect.
2. If the server requires authorization, the TUI starts OAuth automatically and opens your browser.
3. When the browser redirect lands on the TUI's loopback listener, the connection finishes on its own — no second **`c`**.
4. Use the **Auth** tab to inspect the resulting OAuth state, or to clear it.

The TUI's callback listener defaults to `http://127.0.0.1:6276/oauth/callback` — a _fixed_ port, deliberately, because static OAuth apps, CIMD, and enterprise-managed auth all require pre-registered redirect URIs. Register that URI once and it works across sessions.

The trade-off is that only one TUI OAuth flow can hold the port at a time; a second concurrent flow fails with `EADDRINUSE`. Override with `--callback-url` or `MCP_OAUTH_CALLBACK_URL` — use a different fixed port per instance, or `http://127.0.0.1:0/oauth/callback` for an OS-assigned ephemeral port when your authorization server registers redirect URIs dynamically.

<Warning>
  Redirect URIs must match **exactly** what you registered. `localhost` and
  `127.0.0.1` are different URIs as far as an authorization server is concerned.
</Warning>

Per-server OAuth fields in the catalog (static client id/secret, scopes, the enterprise-managed flag) are applied automatically. Install-wide settings — CIMD, enterprise IdP — come from `~/.mcp-inspector/storage/client.json`, the same file the web client's **Client Settings** dialog writes. Point at a different one with `--client-config` or `MCP_CLIENT_CONFIG_PATH`.

See [Authorization](/docs/draft/tools/inspector/authorization) for the full picture.

## Requirements

The TUI needs a real TTY with raw-mode support. It will not run usefully in a headless CI job — use the [CLI](/docs/draft/tools/inspector/cli) there.
